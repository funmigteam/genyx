# انتشار کیف پول، لاتاری و برداشت دستی — 2026-09-16

## نکته فوری برداشت

کد جدید هیچ برداشت خودکاری ارسال نمی‌کند، حتی اگر متغیر قدیمی AUTOMATIC مانده باشد.
تا قبل از انتشار کد، سرور فعلی تغییر نکرده است. در `/opt/genyx/.env.production` مقدار
`PAYOUT_MODE=MANUAL` را قرار دهید و سرویس api را با `--force-recreate` بازسازی کانتینر کنید.
سایر workerها را لازم نیست خاموش کنید.

پیام امضاشده‌ای که قبلاً به شبکه ارسال شده ممکن است هنوز اجرا شود. درخواست‌های قدیمی
دارای PayoutJob را بدون تطبیق تاریخچه ولت دوباره پرداخت، رد، پاک یا requeue نکنید.
خالی‌بودن chainTxHash در دیتابیس به‌تنهایی اثبات عدم پرداخت نیست.

از `--accept-data-loss` استفاده نکنید. بعد از بکاپ:

```bash

```

## بررسی پس از انتشار

- برداشت جدید باید REQUESTED شود، نه صف ارسال خودکار؛ هیچ PayoutJob جدیدی نباید ساخته شود.
- در ادمین مبلغ خالص و مقصد نمایش داده می‌شود. تأیید برای پرداخت دستی هیچ پولی منتقل نمی‌کند.
  فقط پس از پرداخت واقعی، هش hex با ۶۴ کاراکتر را ثبت کنید. هش تکراری رد می‌شود.
- ورودی یک USDT لاتاری، ۱۰ GEN می‌دهد؛ همان درخواست دوباره پاداش نمی‌گیرد.
  ورود رایگان و پیشنهاد دوم بدون هزینه ورود هم پاداش ورود جدید ندارند.
  GEN فعلاً صحیح است؛ بخش کسری GEN به پایین گرد می‌شود.
- نبود موجودی داخلی USDT پیام شارژ و دکمه رفتن به کیف پول را نشان می‌دهد.
- اعداد مثبت تا ۱۲ رقم مجازند؛ سقف ۲۵ وجود ندارد. سقف دو پیشنهاد هر کاربر حفظ شده است.
- لینک تسک باید پیش از claim باز و رویداد آن در سرور ثبت شود؛ این اثبات تماشای محتوا نیست.
- پکیج غیرفعال برای خرید جدید نمایش داده نمی‌شود؛ خریدهای قبلی تغییر نمی‌کنند.
- رفرال‌های بدون پکیج از لیست/شمارش کاربران حذف شده‌اند؛ انتساب معرف برای خرید آینده حفظ شده است.
- پروفایل اشتراکی فقط در صورت فعال‌بودن public profile صاحب پروفایل نمایش داده می‌شود.
- تنظیم هدیه روزانه هنگام ساخت روز جدید snapshot می‌شود؛ جوایز روزهای باز عوض نمی‌شوند.
- حجم تیم با Cycle نمایش داده می‌شود (هر Cycle برابر ۵ USDT حجم). قیمت، هزینه ورود و
  موجودی واقعی همچنان USDT هستند تا مبلغ پرداخت پنهان یا واحد مالی اشتباه نشود.
